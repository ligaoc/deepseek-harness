# @deepseek-ai/dsh-vision-bridge

English | [中文](README.zh.md)

An image-to-text bridge for the harness: when the target model cannot take images, this plugin degrades image blocks in the step messages to descriptions produced by a configured vision endpoint, so text-only models can still answer about attached images. It listens on the `agent/pre-step` waterfall — the same extension point `dsh-tool-skill` uses to inject skill content — so the loop is untouched: the session log keeps the original image blocks, and only the model-facing step messages carry the descriptions.

This is an **implementation** package: a function/namespace plugin (`inject: ['attachments', 'llm']`) that transforms step messages before the model request. It is dormant until a vision endpoint is configured.

## Config

| Key | Default | Meaning |
|---|---|---|
| `apiKeyEnv` | `VISION_API_KEY` | Environment variable holding the vision API key. Empty makes the bridge dormant. |
| `baseURL` | (unset) | OpenAI-compatible vision endpoint base; `/chat/completions` is appended. Unset makes the bridge dormant. |
| `model` | (unset) | Vision model id accepted by the endpoint. Unset makes the bridge dormant. |
| `prompt` | built-in Chinese description prompt | Instruction sent before the image; its output is the description. |

```yaml
- id: vision-bridge
  name: '@deepseek-ai/dsh-vision-bridge'
  config:
    baseURL: https://api.siliconflow.cn/v1
    model: Qwen/Qwen2.5-VL-7B-Instruct
```

## Behavior

The pre-step listener runs after every other listener's `next()` (registration order places degradation last, so injected instructions and skill content are preserved). It degrades only when:

1. the step messages contain an image block, AND
2. the agent's exact target model declares no `image` input modality (absent metadata degrades — an undeclared model cannot be trusted to accept images), AND
3. the bridge is configured (`apiKeyEnv` resolves, `baseURL` and `model` set).

The model is read from the agent-scoped `modelSelection` installed by the runtime entry point (`agentModelSelection`), never the creation-time `agent.options` snapshot — a model switched from the Web UI after session creation is judged by the live selection, the same value the host admission check used.

While the bridge is active it also publishes the `imageDegradation` service (`isActive(): Promise<boolean>`). Host admission preflights (the Web `prompt` and `selectModel` gateways) consult it before refusing an image for a text-only model: with the bridge active the request is admitted and this listener performs the degradation instead of the gateway rejecting it.

Each image block is replaced by a text block `[图片描述] <description>`; a failed vision call degrades to `[图片识别失败: <error>]` instead of blocking the step. Every successful degradation appends a `vision/describe` session event (`attachmentId` + verbatim `text`), so the model request stays reconstructable from the log (Model-visible = logged). The original image blocks remain in the session log unchanged.

A vision-capable target model keeps raw images: the bridge never degrades for a model that declares `image` input.

## Model Experience

The model receives the description text in place of the image, wrapped in the `[图片描述]` marker; the description is generated by the configured vision endpoint, not by the harness model.

#### KV Cache effect

Degradation rewrites the affected step messages, invalidating the request suffix they belong to.

## Known Limitations and Deferred Work

- **One description call per image per step** — repeated turns with the same image re-describe it (no description cache yet).
- **Only `chat/completions`** — other OpenAI-compatible shapes (Responses API) are deferred.
- **Vision endpoint failures degrade to failure text** — no retry or fallback endpoint yet.
